# Capri 0.2.1

Fixes the macOS package signature defect in 0.2.0. Existing menu names and application features are unchanged.

## Fixed

- The complete macOS app bundle, nested Electron components and Swift window helper are now explicitly ad-hoc signed. Bundle resources are sealed under the Capri application identifier.
- Hardened runtime remains enabled, with the entitlements required for Electron JIT and ad-hoc framework loading.
- Packaging fails if strict signature verification rejects the completed bundle.
- CI verifies the actual apps extracted from both ZIP and DMG, launches the ZIP app and checks that modified resources are rejected.
- The macOS updater now verifies the full new bundle with `codesign --verify --deep --strict` instead of only checking that a signature is present.

## Downloads

- Windows x64: EXE installer.
- Linux x64: AppImage and DEB.
- macOS Apple Silicon: DMG and ZIP.

SHA256SUMS.txt, update feeds and blockmaps are included.

## macOS trust and first launch

This corrects bundle integrity; it does not provide Apple Developer ID signing or notarization. The app is ad-hoc signed, so macOS may still block a browser download and require your explicit approval in System Settings > Privacy & Security. CI launch checks do not prove Gatekeeper acceptance. No system security settings are changed by the build or verification process.

For a first installation, use these 0.2.1 packages instead of the defective 0.2.0 Mac packages. Version 0.1.0 has no built-in updater and requires a manual upgrade. Native Wayland remains unsupported.
